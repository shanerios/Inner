# Inner agent notes

## Release notes

After completing a user-visible improvement, update `docs/WHATS_NEW.md` under **Unreleased**. Keep entries concise, factual, and written around the behavior a practitioner will experience. Do not add internal-only refactors, abandoned work, speculative features, or unverified claims.

When preparing a release, reconcile the store-ready draft with the release branch, record the shipped version, build numbers, and date, then create a fresh Unreleased section for subsequent work.
